# تقرير المرحلة 1 — قاعدة البيانات والأمان

## ما تم إنشاؤه
- `original/DWLY_EGY_V1.html` — نسخة طبق الأصل من الصفحة الحالية، للقراءة فقط.
- 5 ملفات migration تنشئ 27 جدولًا، وعرض آمن للمخزون (`variant_stock`)، و9 أنواع enum.
- سياسات RLS على كل الجداول، وصلاحيات بأقل قدر ممكن، وسياسات تخزين صور المنتجات.
- دوال الطلب: `cart_set_item`, `quote_cart`, `place_order`, `customer_cancel_order`.
- دوال الإدارة: `admin_set_order_status`, `admin_set_payment_status`, `admin_adjust_inventory`, `admin_set_account_status`, `admin_dashboard_stats`.
- دالة الدفع: `record_payment_event` (service_role فقط).
- `seed.sql` و`purge_demo.sql`، واختبارات pgTAP، وفاحص ساكن، و`.env.example`.

## ما اختُبر فعلًا
| الفحص | النتيجة |
|---|---|
| `scripts/static_check.py` على المستودع | 195 نجاح، 0 فشل |
| اختبار الفاحص نفسه بـ 7 كسور متعمدة (حذف RLS، سياسة مفتوحة، صلاحية كتابة، search_path ناقص، فتح دالة الـ webhook، مفتاح مسرّب، تعديل V1) | كل الحالات الـ 7 اكتُشفت |
| تطابق SHA-256 لنسخة V1 | نجح |

الفاحص يقرأ نص SQL ويكشف أخطاء البنية والأمان. **لا يُثبت صحة السلوك.**

## ما لم يُختبر بعد (لأن البيئة هنا بدون Postgres وبدون إنترنت)
- أن ملفات SQL تُنفَّذ بدون أخطاء صياغة على Postgres 15+. لم أستطع تشغيلها، فقد تظهر أخطاء صياغة أو أسماء عند أول `supabase db reset`.
- اختبارات pgTAP في `tests/database/` مكتوبة ولم تُشغَّل: عزل بيانات العملاء، منع الكتابة المباشرة، المخزون، تكرار الطلب، الإلغاء، رفض استدعاء الـ webhook من العميل.
- تدفق التسجيل وتأكيد البريد (يحتاج مشروع Supabase حقيقي).
- الأداء تحت ضغط طلبات متزامنة.

## ما يحتاج ربط Supabase لاحقًا
مشروع Supabase، تفعيل تأكيد البريد، منح دور admin لحسابك، ضبط رسوم الشحن، رفع صور المنتجات الحقيقية.

## ما ينتظر قرارًا أو بيانات منك
رسوم الشحن لكل محافظة، صور المنتجات، حساب تاجر Paymob أو Fawry للدفع الإلكتروني، نص الشروط والأحكام، بيانات الاتصال بالمتجر.
